# Rendered narration

## MDAAI
MDAAI is a repository-based protocol for human-directed AI development.

Ordinary files define what an agent may change, what work is current, and what evidence supports a result.

## Original MDAAI
The original template connects Project Elaboration to Work Orders and their registry.

Corrective Work Orders explain errors. Architecture decisions explain choices. Checkpoints capture milestones.

Its Work Order editing rules conflict; adopters must reconcile them.

## MDAAI 2.0
Two point zero keeps a root operating contract and five governance documents.

Project Elaboration owns scope and sequence. TASKS dot JSON is the single owner of task state.

An optional Claude file only points to the contract.

## How files connect
Read the contract, assigned task, scope, and relevant rules.

The task links to scope and evidence. Its owner updates the active row, not a second status list.

Add a decision or durable record only when needed.

## One ordinary task
For a status endpoint, confirm scope, change code and tests, then collect real results.

Update the task with evidence and the next action. Complete it only when acceptance is supported.

Preserve that terminal result; link later corrections.

## From original to 2.0
The practical change is less routine paperwork, not less accountability.

Adopt project by project: reconcile old rules, start a fresh registry, and preserve completed history.

These instructions guide behavior. They do not automatically enforce it.
